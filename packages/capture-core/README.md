# @rivetos/capture-core

Shared HTTP capture writer for short-lived harness hooks; the den owns database connections and transactional dedupe at `POST /api/capture`. `createCaptureWriter({ denUrl })` posts batches, drains up to 50 pending batches first, and spools network/5xx failures to private, atomically published JSON files in `~/.rivetos/capture-spool`; 4xx throws and replay moves rejected files to `dead/`. TLS trust is supplied by the launcher through `NODE_EXTRA_CA_CERTS`; `resolveDenUrl` returns the endpoint and CA path without changing TLS settings.

`write()` caps each message's `content` and `tool_result` at 16,000 UTF-16 units the same way the den does (`full_content_length` / `full_tool_result_length`, `truncated: true`, high-surrogate back-off, no inline marker), then posts chunks whose JSON is at most `maxChunkBytes` (default 768 KiB). Each chunk repeats the batch header. `finalize` is set only on the last chunk. A message that is still over the chunk budget is sent alone with `tool_args` replaced by `{ "_elided": true, "bytes": n }` and `metadata.full_tool_args_length` set to that UTF-8 byte length. Every chunk delivered returns `CaptureResult` with summed `inserted` / `skipped`. At least one spooled chunk and no double-failure returns `{ spooled: true, file, files }` (`file` is the first spool file). Any chunk that fails both delivery and spooling returns `{ spooled: false, error }` — earlier chunks stay delivered or spooled, and the caller must not advance its cursor. Spool failures are logged and returned without throwing; only HTTP 4xx errors throw. A 413 on replay is still moved to `dead/` and not retried.

The helpers are not all drop-in copies of the Codex helpers: `capForStorage(text, { limit })` is the hard-cap API, returning `{ text, truncated, fullLength }` with no inline marker and no pointer argument. `loadEnvFile(path)` requires an explicit path and returns a record without touching `process.env`; callers must apply that record themselves. `isRecord`, `asString`, and `safeJson` are the Codex originals, including `safeJson`'s `String(v)` fallback.

`resolveDenUrl` returns `caPath` without checking whether the file exists; the launcher checks CA existence and disables den transport when it is missing.

`resolveCaptureTransport(env)` picks `den`, `pg`, or `none`. `RIVETOS_CAPTURE_TRANSPORT=den|pg` forces; the default is `den` when `resolveDenUrl` resolves and `RIVETOS_USER_ID` is unset or `''`, else `pg` when `RIVETOS_PG_URL` is set. Any other user id, including whitespace, never selects `den`. A launcher that found no CA file unsets `RIVET_DEN_URL` and leaves `RIVET_DEN_CA`, which selects `pg` instead of the default URL. `withFileLock(dir, fn)` is the cross-process state lock. `dir` persists (`mkdir -p`, never removed). The holder writes the full body to `.publish.<hostname>.<pid>.<startTimeMs>.<random>` (`wx`, mode `0600`, fsync) and renames it to `owner.<token>`. That name is unique, so the rename cannot clobber another owner, and the final file is never empty or partial. It unlinks only that name on the way out, including when `fn` throws. A lock file is removed by another process only when its creator is provably dead (same host, `kill(pid, 0)` → ESRCH); lock directories must be host-local (`~/.rivetos`), a foreign-host owner file blocks until its creator removes it. Liveness is the filename, so an empty or invalid body does not preserve a dead same-host file. `.publish.*` temps are ignored by the scan and removed only when that same-host pid is dead (`ESRCH`). The holder refreshes its own mtime every `staleMs / 3` (default 40s) for operators; that heartbeat is not a reason to remove a file. When several live owners are present the lexicographically smallest token stays and the others drop their own files and retry; the smallest waits until it is alone. `LockTimeout` fires after `waitMs` (default 10s). `eventIdFromContent` is the SHA-256 id for messages that have no native id; pass `occurrence` to fold a repeat index into the hash. `occurrenceIndex` and `contentTupleHash` are the matching helpers for an id that keeps the index outside the hash.
