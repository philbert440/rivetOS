Not a black box

You keep this one.

Most “AI memory” products are an account on someone else’s cluster. You send them sessions. They decide the export, the retention, and when the API changes.

RivetHub is software you install. The hub, the database, and the mesh certificates live on hardware you pick. We do not run a Rivet account for you, and the runtime does not phone home.

Self-hosted on your hardware

Linux or macOS for the local hub; Debian or Ubuntu for a dedicated server. No Rivet login. The process listens on your machine — https://localhost:5174 on a laptop.

02

Local-first memory

Default install uses embedded PGlite on that host. Full-text and fuzzy search work with no embedding API. Semantic search is optional, and only talks to an endpoint you configure.

03

Mesh of nodes you enroll

A second machine joins over SSH to your hub and receives certificates from your CA. There is no Rivet-operated mesh for you to join.

04

MCP-exposed to tools you choose

Connected coding tools search the hub through MCP you install locally. You pick the harnesses. Rivet does not proxy those sessions.

How it works

The record stays on your hub.

Install once, connect your tools, keep working. Capture, recall, and the original source all live on the hub you run.

Capture

Sessions save on your hub.

As you work, RivetHub writes each session to the hub you installed — prompts, tool calls, results — from whichever supported tool you are in. Nothing to export to a vendor inbox.

Two paths

Same software. Different topology.

Start on one machine. Put the hub on a dedicated box later if you want always-on, shared memory. Both are RivetOS from philbert440/rivetOS.

Path A · default

Local-only

One machine is the hub and the agent node. Embedded PGlite, local CA, connected tools, desktop or browser on https://localhost:5174. This is the start.

Path B · when you want a dedicated hub

Data hub + nodes

Install the datahub on a Debian or Ubuntu host, then enroll agent nodes over SSH. Memory stays on that hub. Agents run on the machines you enroll.

on the node, once the datahub is up

Grow later

Add a node. Move the hub when localhost is too small.

A laptop install is a complete hub. When you want a second machine, run the hub helper on that laptop first, then enroll the new node. When you want the hub off localhost, stand up a dedicated datahub and enroll machines into it. Backup the local store first (rivetos local backup). There is no one-shot migrate CLI — same software, new topology, documented installers.

What you get

A hub, a memory plane, and the tools already on your PATH.

Search from the first session

Full-text and fuzzy search are built in. No model to configure. Semantic search is an optional OpenAI-compatible embedding endpoint — local or cloud — that you point the hub at.

The record stays on the machine you chose

No Rivet account. Agent providers still see the prompts you send them. Optional embedding or compaction services see what you send them. Everything RivetHub stores stays on your hardware until you move it.

One repo, two topologies

RivetHub is the install and the human UI for RivetOS. Releases are pinned to tags and checksums. Backups are rivetos local backup on a laptop, or your own Postgres backup on a datahub.

Questions

Asked often.

What is RivetHub?

The self-hosted hub and human UI for the RivetOS runtime: a personal AI agent runtime and memory plane. It records sessions, tool calls, and outputs from connected tools, and makes that history searchable by you and by those tools over MCP.

Is this the same repo as RivetOS?

Yes. One product, one repository: github.com/philbert440/rivetOS. rivethub.io is the get-started surface. rivetos.dev is the deep reference. Same runtime, same memory plane.

Is this SaaS?

No. You install the software. There is no Rivet-hosted tenant for your agents or memories. This website may record anonymous pageviews and named install-CTA clicks; the hub you run does not phone that usage home. See privacy.

Where does my data live?

On the hub you installed: PGlite under ~/.rivetos in local mode, or Postgres on a datahub you stand up. Agent providers still process the prompts you send them. If you configure cloud embedding or compaction, those services process what you send them. Choose local services and that extra hop stays local.

Which tools does it work with?

Claude Code, Codex, Grok Build, Kimi Code, and Hermes. The installer wires capture and recall into whichever of the shipped tools it finds — the quickstart shows exactly how each one connects.

Do I need an embedding model to start?

No. Search works out of the box. Semantic search is an optional upgrade that uses an embedding endpoint you choose and configure on the hub.

Can I run the hub on Windows?

The hub installer supports Linux and macOS. On Windows, the desktop app connects to a hub running elsewhere — your Linux server or another machine on the network.
