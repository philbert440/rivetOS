releases

Tagged, checksummed, never rebuilt

The RivetHub runtime is released on GitHub from philbert440/rivethub-runtime. Every tag publishes one archive per platform and a SHA256SUMS file, and a published archive is never replaced, so a pinned URL and checksum stay valid.

archives

What a release contains

Tag v<version> publishes, at https://github.com/philbert440/rivethub-runtime/releases/download/v<version>/:

rh-<version>-x86_64-unknown-linux-gnu.tar.gz
Linux x86_64, built on Ubuntu 22.04 (glibc 2.35 or newer)
rh-<version>-aarch64-unknown-linux-gnu.tar.gz
Linux aarch64, built on Ubuntu 22.04 (glibc 2.35 or newer)
rh-<version>-universal-apple-darwin.tar.gz
macOS, Apple Silicon and Intel in one binary
SHA256SUMS
the SHA-256 of each archive

Each archive holds rh, rivethub-migrate and LICENSE. Windows users run the Linux archive under WSL. Before upload, every build unpacks its archive and checks that rh version names the release, that rh db migrate creates a fresh store, and that rh doctor passes on it. The Quickstart has the download-and-verify commands.

channels

Beta and stable

Every merge to main tags the next patch version and publishes it as a beta (a GitHub prerelease). A beta becomes stable when it is promoted, without being rebuilt. rh update follows a channel:

terminal 
$ rh update --channel beta
$ rh update --channel stable
$ rh update --channel beta --version v0.7.0

Beta installs the highest version published, prereleases included; stable installs the latest promoted release and refuses prereleases; --version pins an exact tag (a beta tag with --channel beta). The updater checks the archive against SHA256SUMS, migrates the configured memory with the new rivethub-migrate, swaps both binaries (keeping *.previous copies) and restarts the systemd unit unless you pass --no-restart. --mesh updates every node in the mesh to the release installed locally.

Use beta for now. The newest releases are betas, and the stable channel still resolves v0.1.4, which refuses the current memory schema. Install and update with --channel beta until a 0.7 release is promoted.

the rest

Desktop, plug-ins and Android

  • Desktop: rivethub-desktop has no binary releases yet; build it from main with packaging/linux/install.sh.
  • Plug-ins: rivethub-plugins holds the SDKs, templates and plug-ins as source; each pins the runtime contract it was built against.
  • Android: apps/rivethub-android in the rivetOS repository, built from source.

earlier releases

The TypeScript RivetOS feed

Before rh, RivetHub shipped the TypeScript RivetOS runtime through the get.rivethub.io installers (local.sh, datahub.sh, node.sh), pinned by pins/stable.json, with the 0.5 desktop and Android downloads listed in releases/latest.json. Those still install that runtime, which rh supersedes; existing installs move with Migrating to RivetHub.
