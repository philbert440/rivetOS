Server setup

A hub that’s always on.

Put RivetHub on a server, VM, or Linux container so your memory is always on and shared by every machine you work on: a Postgres datahub holds the memory, and every machine runs an rh node against it.

Setting up your own laptop? The Quickstart is the shorter path.

The hostThe datahubNodesVerify

Step 01 · the host

Any Linux box with systemd.

Dedicated server

Linux on x86_64 or aarch64 with glibc 2.35 or newer and systemd, on an address your nodes can reach.

Virtual machine

The same, inside a VM. Give it a stable address for the database and the certificate authority.

Container

A Linux system container with systemd works the same way: rh is a single binary with nothing else to install.

Step 02 · the datahub

Set up the datahub.

Postgres 16 with pgvector holds the memory. Create the database, run the one-time superuser steps, install the job queue, then bring the schema up to date before anything connects:

on the datahub 
$ rivethub-migrate postgres --config ~/.rivethub/config.yaml

Then start the memory workers (rh worker --role …) and, for a mesh, step-ca.

Datahub guide →

Step 03 · nodes

Run a node on each machine.

A node is where your agents and their tools live. Install rh, point its config at the datahub, and run it under systemd:

on each node 
$ rh config validate
$ rh service init
$ rh service start

Nodes that serve other machines take certificates from step-ca and join the mesh.

Node guide →

Step 04 · verify

Check it, then get to work.

  1. On the datahub: rivethub-migrate status postgres --config ~/.rivethub/config.yaml shows nothing pending, and rh memory queue-status shows the workers taking jobs.
  2. On each node: rh doctor, then rh status.
  3. Connect a tool, run a small task, and find it with memory_search from another tool, or in the desktop app.
