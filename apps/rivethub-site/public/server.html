Always within reach.

Run RivetHub on a server, VM, or Linux system container. Set up a datahub for shared memory, then enroll an agent node to run your agents.

Setting up your own development machine? Start with the Quickstart.

01 / Choose where it runs

A Linux host, your way.

Server

Use a dedicated Debian 12 or Ubuntu LTS machine with systemd and sudo access.

Virtual machine

Install the same supported Linux distribution in a VM. Give it an address your agent nodes can reach.

Container

Use a Linux system container that supports systemd and the installer’s requirements. On a Docker host, the installers’ --docker option runs their services in containers managed by the host’s systemd.

Review disk, networking, and dependency requirements in the datahub guide and agent node guide.

02 / Store the collection

Install the datahub.

The datahub provides Postgres with pgvector, the memory schema, and the certificate authority. Run its installer from a rivethub-distro checkout on the hub host:

sudo bash install/datahub.sh

The wizard asks for the owner, memory mode, and installation mode. Choose lite to begin without inference workers, or full to configure embedding and compaction endpoints and models.

For Docker-managed Postgres, use sudo bash install/datahub.sh --docker. Docker must already be installed on the host.

03 / Run your agents

Enroll an agent node.

The agent node runs the RivetOS runtime and joins your datahub over SSH. On the node host, prepare an SSH login that can run rivethub-hub on the datahub, then follow the node installer:

sudo bash install/node.sh --hub owner@192.0.2.10

Run this from a rivethub-distro checkout. Replace owner@192.0.2.10 with your datahub’s SSH login. The guide covers root’s SSH access, node identity, Docker mode, and certificate enrollment.

Full agent node setup →

04 / Make the first connection

Check it. Then start working.

  1. On the datahub, run rivethub-hub status.
  2. On the agent node, check systemctl status rivetos-agent.service and run sudo -u rivet -H rivetos doctor.
  3. Connect a RivetHub app to your node. Run a small task through a connected harness, inspect its captured session, and ask the agent to recall it.
