Quickstart / Local development setup

Up and running.
On your own machine.

Datahub, agent and den together. One command takes you from an empty machine to local memory and your first chat.

InstallHarnessesPair a phoneEveryday commands

01 / what you get

Everything in
one place.

  1. Runtime + embedded Postgres. PGlite runs the memory engine without a separate database server.
  2. Your own CA + TLS. A local certificate authority and HTTPS on port 5174.
  3. Your harnesses, connected. Detection, memory capture and recall for the supported tools already on your machine.
  4. The desktop app. Installed and launched on Linux; it finds localhost automatically. macOS desktop is coming — use the browser there.
  5. A next-steps banner. The installer points you to your local node and what to do next.

Requirements

Linux or macOS · Node.js 22+ (installed for you if missing) · ~1 GB RAM for the memory engine · ~200 MB disk to start.

02 / the command

Make yourself
at home.

on your laptop 
$ curl -fsSL https://get.rivethub.io/local.sh | bash

This is the stable laptop installer. Desktop and Android first downloads are on this site. Dev/nightly builds for in-app Updates live on the mesh share. Release details →

The installer reports setup progress, the harnesses it detects and a banner with next steps. When it finishes, your local node is at https://localhost:5174.

First chat. Open the RivetHub desktop app — it connects to localhost by itself — or open the local address in your browser. On macOS, use the browser while the desktop app is coming.

04 / pair your phone

Your node.
Another screen.

Start in Settings → Devices on the desktop. The QR connects your phone to your node.

Get the apps →
Android

Scan. Open. Connected.

  1. Install the RivetHub Android app.
  2. Open Settings → Devices on the desktop and scan its QR with your phone.
  3. The app pulls its certificate and passphrase and connects to your node.
iPhone

A home in Safari.

  1. Open Settings → Devices on the desktop.
  2. Scan the QR on your iPhone. Open the pairing page in Safari and install its profile.
  3. Use RivetHub in Safari. A native iPhone app comes later.

05 / your memory

Context that
stays with you.

Capture saves the conversation

As you use a connected harness, memory capture records conversation context in the local memory engine. Your captured memory stays on your machine.

Recall brings it back

Inside Claude Code, Grok Build, Codex, Kimi Code, and Hermes, recall makes relevant saved context available to the harness. You keep working in the tool you know.

Full-text and fuzzy search work from day one. Semantic search is opt-in: use --memory full with any OpenAI-compatible embedding endpoint. That endpoint processes embedding requests; choose where it runs.

06 / grow into a mesh

You already
started one.

Your laptop was a mesh of one all along. Run this on another machine to join it to your laptop:

on the next machine 
$ curl -fsSL https://get.rivethub.io/node.sh | sudo bash -s -- --hub user@192.0.2.10

Replace user with your SSH login and 192.0.2.10 with your laptop’s address. See the node guide for the joining machine’s requirements.

One prerequisite: your laptop must be set up as a hub before another machine can enroll into it — local mode does not install the hub helper on its own. See the datahub guide to enable enrollment on your laptop first.

07 / everyday commands

A little
housekeeping.

Check the local node

terminal 
$ rivetos local status

Back up your local setup

terminal 
$ rivetos local backup

Reset local mode

Back up before resetting your local setup.

terminal 
$ rivetos local reset

Uninstall

Back up first, then check the installed CLI’s local help for its uninstall instructions. Remove the desktop app through your operating system.

terminal 
$ rivetos local --help

08 / troubleshooting

When something
gets in the way.

Node not running

Memory capture pauses while the local node is stopped. Run rivetos local status to check it, and restore the node before continuing capture.

Port 5174 is busy

Check which application is using port 5174. Stop that application if it is safe to do so, then retry local setup.

Unsigned macOS app

For an unsigned macOS build, right-click the app and choose Open. The macOS desktop release is coming; the browser at https://localhost:5174 is the current path.
