# RivetOS memory for DeepSeek Harness (dsh)

Persistent, cross-agent memory for dsh: every session is captured into the
shared RivetOS store under **agent `rivet-deepseek`, channel `dsh`**, and the
model gets `memory_*` recall tools over every other Rivet agent's history.

This integration targets the same fidelity as `integrations/claude-code` and
`integrations/grok`.

## What it does

| Piece | Path | Role |
|---|---|---|
| Cordis plugin | `plugin/index.mjs` | Subscribes to dsh's `session/event` firehose, spools one op per event, detaches a worker |
| Capture worker | `capture/deepseek-memory-capture.mjs` | Parses events + zstd transcripts, dedups, writes to Postgres |
| MCP launcher | `bin/dsh-memory-mcp.sh` | stdio MCP server exposing `memory_search`, `memory_browse`, `memory_stats`, `memory_get_full`, `memory_tags`, `wiki_*` |
| Setup script | `bin/setup-dsh-rivet-memory.sh` | Wires the bundle + MCP into a dsh profile |

## Capture model

dsh has no Claude-style lifecycle hooks. Capture has two layers, mirroring
Claude Code's `UserPromptSubmit`/`PostToolUse` plus `Stop`/`SessionEnd`:

1. **Live** — the plugin spools each interesting `session/event`
   (`user/message`, `assistant/message`, `tool/call`, `tool/result`,
   `turn/end`, `session/title`) and a detached worker ingests it.
2. **Reconcile** — at every `turn/end` the plugin *also* spools a `reconcile`
   op that re-reads the whole `session.v4.jsonl.zstd` transcript and inserts
   only the rows the live stream missed. This is the self-healing path: a
   dropped listener, a killed worker, or an offline datahub leaves a hole that
   the next turn boundary repairs. Ingest dedups per event id, so reconcile is
   safe to run on every turn.

Ingest is serialized per session with `pg_advisory_xact_lock`, so concurrent
workers (live + reconcile + backfill) cannot double-write.

### Dedup

Primary key is the dsh event identity: message `uuid`, or `callId` for tool
rows, falling back to `session + seq`. Content hashing is a namespaced last
resort, so two legitimate `ok` turns never collapse.

Verified: re-ingesting an already-captured 28-message session reports
`inserted=0 skipped=28`.

### Tool rows

dsh emits tool calls and results as **separate events**. Storing them verbatim
yields two rows per invocation — one with `tool_args`, one with `tool_result` —
which reads poorly on recall because a result row loses the arguments that
explain it.

`foldToolResultsInto` folds each result into its originating call row by
`callId`, so one row carries name, arguments and output — the same shape
claude-code and grok-build store. Unpaired results are kept, so a result whose
call never arrived is still captured, and the result's transcript line is
recorded as `extra.resultLineIndex` for disk-backed recovery.

Measured on a real session: 7 tool rows, all 7 carrying both arguments and
result.

### Transcript discovery

dsh versions its transcript filename — `session.v4.jsonl.zstd`. Any anchored
`session.jsonl` pattern matches **zero** files on a real install and silently
disables the backstop. Discovery accepts an optional version segment:

```js
/^session(\.[a-z0-9]+)?\.jsonl(\.zstd|\.zst)?$/
```

## Install

```sh
# Wire into a profile (default: the profile dsh boots without --profile)
integrations/dsh/rivet-memory/bin/setup-dsh-rivet-memory.sh --profile desktop --apply

# Capture any transcripts that predate the install
node integrations/dsh/rivet-memory/capture/deepseek-memory-capture.mjs \
  --backfill "$DSH_HOME/sessions"
```

The launcher reads `~/.rivetos/.env` for `RIVETOS_PG_URL`,
`RIVETOS_EMBED_URL` and `RIVETOS_EMBED_MODEL`. Embeddings are generated by a
Postgres insert trigger, so captured rows embed automatically.

## Verify

```sh
# transcripts discovered
node -e "import('./capture/deepseek-memory-capture.mjs').then(m=>console.log(m.findSessionFiles(process.env.DSH_HOME+'/sessions').length))"

# capture activity
tail -f ~/.rivetos/deepseek-memory-capture.log

# tools reachable
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"p","version":"0"}}}' \
  '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}' \
  | bin/dsh-memory-mcp.sh 2>/dev/null
```

## Known constraints

- The `desktop` profile is managed by the Electron app and cannot be booted
  from the CLI; its config is validated by composition instead.
- `dsh-memory-mcp.sh` prefers a **built** install root. Root discovery accepts
  any checkout with `nx.json` + `services/mcp-sidecar`, including an unbuilt
  source tree, so the launcher falls back to a built root before failing.
- The MCP sidecar refuses to start when `RIVETOS_EMBED_URL` is set without
  `RIVETOS_EMBED_MODEL`; the launcher supplies the house default when the env
  file does not.
